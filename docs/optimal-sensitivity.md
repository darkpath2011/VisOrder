# 如何计算最适合用户的灵敏度

> 讨论稿。目标：在 VisOrder 瞄准训练器里，给出一套有科学依据、可落地的「推荐灵敏度」算法与产品流程。  
> 现状锚点：`src/lib/aim-trainer/core/sensitivity.ts`、`store/profiles.ts`（已有 VALORANT / CS2 的 yaw 与感度换算）。

---

## 0. 学科边界（我们站在哪几条线上）

| 领域 | 关心什么 | 对感度校准的直接意义 |
| --- | --- | --- |
| **心理物理学 Psychophysics** | 刺激变化 ↔ 主观感受 | 校准步长、可察觉差异（JND） |
| **人机交互 HCI** | 交互参数 ↔ 效率与体验 | Fitts / CD Gain：任务与增益不可拆开 |
| **运动控制 Motor Control** | 精度、速度、反馈、误差修正 | 过冲、修正次数、速度—准确性权衡 |
| **实验设计与统计学习** | 用数据估计个体最适参数 | 重复测量、随机化、独立验证 |

---

## 1. 必须先拆开的两个「最优」

这两个结果**不一定相同**；科学上也不能简单认为「灵敏度越高，反应越快」。

| 概念 | 定义 | 典型指标 |
| --- | --- | --- |
| **客观最优灵敏度** \(S^*_{\text{obj}}\) | 完成任务时准确率、速度、稳定性达到较好平衡 | MT、命中率、过冲、修正次数、轨迹偏差 |
| **主观舒适灵敏度** \(S^*_{\text{sub}}\) | 感觉自然、舒适、容易控制 | Likert 舒适度、偏好选择、疲劳自评 |

**产品含义：**

- 内部应**分别记录**客观表现与主观评分，不要混成一个黑盒分数就宣称「最佳」。
- UI 可输出：`推荐（表现）` + `你更偏好的附近值`，或给出帕累托区间让用户选。

---

## 2. 不存在全局绝对最佳值

个体与情境会改变最适参数。更合理的研究对象是：

\[
S^* = f(U, D, T, E)
\]

| 符号 | 含义 | VisOrder 侧例子 |
| --- | --- | --- |
| \(U\) | 用户个体特征 | 腕/臂习惯、练习量、感知与运动能力 |
| \(D\) | 输入设备 | DPI、鼠标、垫子行程、是否关加速 |
| \(T\) | 任务类型 | flick / 微调 / tracking / 多目标切换 |
| \(E\) | 使用环境 | FOV、分辨率、桌面空间、疲劳状态 |

支撑证据之一：Senanayake & Goonetilleke (2016) 在 steering 任务中发现，不同难度下弹道控制与视觉反馈控制的最佳设置可能不同；设备选择也需同时考虑表现与舒适度。

→ **第一版算法就必须声明任务族**（例如「以射击游戏常见指向任务为主」），而不是宣称跨一切场景的唯一感度。

## 3. 核心科学理论 → 产品约束

### 3.1 费茨定律（Fitts' Law）— HCI

\[
MT = a + b \log_2\left(1 + \frac{D}{W}\right)
\]

- \(MT\)：完成指向所需时间  
- \(D\)：起点到目标距离  
- \(W\)：目标宽度  
- \(a,b\)：由实验估计  

**现象：** 目标越远、越小，完成通常越慢。  

**对校准的硬约束：**

- **不能脱离操作任务单独找最佳感度。**
- 大范围快速转向可能偏好较高增益；小范围精确定位可能偏好较低增益。
- 校准关必须覆盖一组有代表性的 \((D, W)\) / 难度（ID），否则推荐会偏某一任务。

Shoemaker 等 (2012) 进一步表明：在增益变化较大时，**两段式（Welford 类）模型**往往比单段 Fitts 更能描述表现；增益升高时，目标宽度相对难度贡献（参数 \(k\)）会系统性变化。启示：增益改变的不只是「快一点」，而是**难度结构本身在变**。

### 3.2 韦伯定律（Weber's Law）— 心理物理学

\[
\frac{\Delta I}{I} = k
\]

- \(I\)：原始刺激强度（此处可近似为当前增益 / cm/360 的倒数等）  
- \(\Delta I\)：恰可察觉的变化量（JND）  
- \(k\)：韦伯分数  

**现象：** 同样 +5 感度数值，在低感区与高感区主观变化量往往不同。  

**对产品的硬约束：**

- 校准与微调**不要用固定绝对步长**（例如一律 ±0.05 in-game），应优先用**相对变化**（如 ±5% / ±10% cm/360，或对数网格）。
- 韦伯定律描述的是**辨别阈限**，**不直接给出**最佳操作灵敏度；它约束的是「怎么搜、怎么调」，不是「搜到哪」。

### 3.3 控制—显示增益（Control-Display Gain）

鼠标场景：

\[
G = \frac{\text{显示端指针（或视角）位移}}{\text{物理鼠标位移}}
\]

与本项目的对应关系（无加速、raw）：

```text
视角侧：rad_per_count = sens × yawDeg × π / 180
物理侧：需 DPI（counts/inch）才能落到 cm/360 / 真实 CD gain
```

Casiez 等 (2008)：恒定增益与指针加速都会影响操作时间与超调等；最优增益不能脱离目标大小、移动距离、设备等因素单独决定。低增益常因 clutching / 肢体速度上限而明显变差；过高增益对极小目标更伤精度。

**对 VisOrder：**

- 游戏感度数字只是 \(G\) 的一种编码；算法内部应使用 **cm/360 或 rad_per_count + DPI**。
- 当前工程已有 `radPerPixel`；缺的是 **DPI 入参** 与 **cm/360 ↔ sens** 双向换算，以及「恒定增益假设」（用户应关闭系统/游戏加速）。

### 3.4 速度—准确性权衡（Speed–Accuracy Tradeoff）

| 表现模式 | 可能解读 |
| --- | --- |
| 很快但经常超过目标 | 可能过于敏感 |
| 很慢但准确率很高 | 可能过于保守 |
| 快且准确 | 较好的操作表现 |
| 快但反复修正 | 初始控制策略不稳定 |

**硬约束：不能仅凭操作速度判断灵敏度是否合适。** 综合分至少要同时包含速度、精度、过冲/修正。

## 4. 统一度量（工程）

游戏内 Sensitivity 不可跨游戏比较。

| 量 | 含义 | 公式（无加速、raw input） |
| --- | --- | --- |
| **eDPI** | 有效 DPI | `DPI × in-game sens`（同游戏内可比） |
| **cm/360** | 转一圈划多少厘米 | `cm/360 = 2.54 × 360 / (DPI × sens × yawDeg)` |
| **°/count** | 每 count 转多少度 | `sens × yawDeg` |

当前档案 yaw：VALORANT `0.07`；CS2 `0.022`。

**建议：** 搜索与推荐一律在 `cm/360`（或等价增益）空间做；UI 再反算当前 `GameProfile` 的 in-game sens。候选网格用**对数 / 等比**排布，呼应韦伯定律。

## 5. 有科学依据的研究框架（推荐算法骨架）

把「找最适感度」当成**个体参数估计实验**，而不是一次排行榜：

```text
1. 用户基线测试
   → 基础操作能力、可选：相对变化可察觉性（粗测 JND）

2. 控制参数实验
   → 多个灵敏度（增益）条件；条件顺序随机化

3. 行为数据采集
   → MT / 准确率 / 轨迹偏差 / 修正次数 / 过冲
   → 同时采主观舒适度（每条件后短评或强制二选一）

4. 个体模型拟合
   → 响应曲线、回归、置信区间；客观与主观分开拟合

5. 推荐个体参数
   → 兼顾效率、准确性、舒适度；给出点估计 + 区间

6. 独立验证（hold-out）
   → 用未见过的短测确认推荐，禁止「用训练数据证明自己」
```

### 实验原则（不可省）

1. **同一用户重复测量**，降低偶然表现。  
2. **条件顺序随机化**，抑制练习效应与疲劳顺序偏差。  
3. **客观 / 主观分开记录**。  
4. **独立测试验证**推荐参数。  
5. 任务设计覆盖不同 ID（Fitts）与任务族（flick / 微调 / tracking）。

### 与先前「路线 A/B/C」的映射

| 路线 | 科学地位 | 说明 |
| --- | --- | --- |
| A 经验区间 + 自报 | 弱先验 / 冷启动 | 可作 \(S_0\)，不能当最终 \(S^*\) |
| B 多条件网格 + 拟合 | **主路径** | 对齐上表框架；步长用相对网格 |
| C 在线小扰动 | 纵向精修 | 需更强统计与防混淆；适合校准后的日常收敛 |
| D 人体工学启发式 | 辅助约束 | 垫子行程等作为搜索上下界，不作唯一答案 |

## 6. 客观指标（候选，供拟合用）

### 6.1 任务表现

- 命中时间中位数（MT）  
- 首次过冲角 / 超调幅度  
- 修正次数（方向反转）  
- 落点散布  
- 重复方差（稳定性）  

### 6.2 运动学

- 峰值/平均速度  
- 减速段平滑度  
- 路径效率（实际路径 / 直线距离）  

### 6.3 主观

- 舒适度、跟手感、疲劳  
- 推荐后允许相对步长微调（如 ±5% cm/360），不锁死单点  

综合分示例（权重待定；须可解释）：

```text
S_obj(G) = w1·速度分 + w2·精度分 − w3·过冲 − w4·抖动
S_sub(G) = 舒适评分（或配对偏好胜率）
最终推荐 = 在 S_obj 可接受带内最大化 S_sub
         或 展示帕累托前沿让用户选
```

## 7. 任务设计（测感度专用）

必须对增益变化敏感，并尽量解耦枪械/地图知识；用 \((D,W)\) / 角距离 × 目标角宽 明确难度。

| 任务 | 测什么 | 增益过高 | 增益过低 |
| --- | --- | --- | --- |
| 固定角度 flick | 弹道段到位 | 过冲、来回修 | 到达慢、欠冲 |
| 微修正 | 视觉反馈精定位 | 难停在像素级 | 更稳但慢 |
| 水平 tracking | 持续控制 | 抖动、蛇形 | 滞后 |
| 多目标切换 | 重置与节奏 | 过头切丢 | 切换偏慢 |

**待讨论：** 复用 `gridshot` / `sixshot`，还是独立 `sens-finder`（更易控制 ID 与随机化）？

## 8. 多源训练数据：哪些能综合进灵敏度估计

VisOrder 里其实有两套训练：**认知钻**（`/train` 目录）与 **瞄准模式**（aim-trainer）。它们采到的量不同，对 \(S^*\) 的可用层级也不同——**能综合，但不能一锅炖成同一个分数去推感度。**

### 8.1 现有数据盘点

#### A. 认知钻（`TRAINING_CATALOG`）

| 训练 | 主要测什么 | 当前结果字段 | 与 CD Gain / 感度的关系 |
| --- | --- | --- | --- |
| 舒尔特方格 | 视觉搜索 + 选择性注意 | `durationMs`（历史仅 schulte 持久化） | **弱间接**：测的是注意/搜索，点击走的是 **OS 指针增益**，不是游戏 `sens` |
| 字色干扰 Stroop | 抑制控制 | `durationMs` + `accuracy` | **几乎无关**：按键/点选决策，不测视角增益 |
| 数值干扰 | 规则 vs 视觉显著性 | 同上 | **弱间接**：有序列点选，但仍是 OS 指针 |
| 序列记忆 | 工作记忆 | 同上 | **无关**（认知容量） |
| 反向线索 | 抑制文字、跟视觉 | 同上 | **弱间接**：决策抑制，非鼠标增益 |
| 视觉完形 | 整体识别 | 同上 | **无关** |

现状：suite 结果多在内存汇总；只有舒尔特写入 `visorder.training.history.v1`（`durationMs`）。**没有感度条件标签，也没有轨迹级数据。**

#### B. 瞄准模式（同一套 `setSensitivity` / `radPerPixel`）

| 模式 | 任务形态 | 当前结算 | 与感度关系 |
| --- | --- | --- | --- |
| `gridshot` / `gridshot3x3` | 多目标切换 / 网格指向 | `score, hits, shots, accuracy, avgKillTime` | **强相关**：同一 CD gain 管道 |
| `sixshot` / `sixshotBeginner` | 少目标、偏大动作切换 | 同上 | **强相关** |

现状：`LocalScoreStorage` **只存每个 mode 的 best score**。局内其实有 accuracy / avgKillTime，但**未按局、未按当时 sens 落库** → 几乎无法事后做 \(S^*(G)\) 拟合。

### 8.2 综合原则（按科学框架分层）

回忆 \(S^* = f(U, D, T, E)\)。不同训练应进入不同槽位：

```text
┌─────────────────────────────────────────────────────────┐
│  直接估计 S*(G)     ← 仅「同增益管道 + 多 G 条件」数据     │
│  例：gridshot / sixshot / 专用 sens-finder（标签含 G）   │
├─────────────────────────────────────────────────────────┤
│  协变量 / 先验 U    ← 认知钻、长期表现基线                 │
│  例：注意速度、抑制错误率 → 调整搜索范围或置信度，不直接改 G │
├─────────────────────────────────────────────────────────┤
│  任务族权重 T       ← 各 aim 模式上的相对强弱               │
│  例：grid 强、six 弱 → 微调任务 vs 大动作任务的推荐侧重     │
├─────────────────────────────────────────────────────────┤
│  不进感度模型       ← 纯记忆/完形等与指向增益无关的分数     │
│  仍可用于「今日状态 / 是否适合做校准」的门控                │
└─────────────────────────────────────────────────────────┘
```

**禁止：** 把 Stroop 正确率、序列记忆、舒尔特秒数和 aim score 加权平均，当成「一个综合分」去反推 in-game sens。那会把 \(U\) 的噪声当成 \(G\) 的信号（混淆）。

### 8.3 可以怎么综合（可行配方）

| 层级 | 做法 | 需要补的数据 |
| --- | --- | --- |
| **L1 瞄准局日志** | 每局写入 `{modeId, sens/cm360, DPI, score, acc, avgKillTime, ts}` | 扩展 `scoreStorage` → session log |
| **L2 同 G 多任务融合** | 固定感度下，用 gridshot + sixshot 的 \(S_{\text{obj}}\) 做加权或分层推荐（大动作 vs 微调） | L1 + 明确任务族权重 |
| **L3 认知先验** | 用舒尔特/干扰类速度与准确率估 \(U\)：冷启动搜索区间宽窄、校准时长、置信度折扣 | suite 结果持久化 + 特征定义 |
| **L4 状态门控** | 认知套件异常差（疲劳/分心）时推迟校准或降低本次推荐权重 | 近期 drill 趋势 |
| **L5 专用校准** | 仍保留随机化多 G 实验作 \(S^*\) 主估计；日常训练只做精修/验证 | sens-finder 或标签化日常局 |

示意（不是最终公式）：

```text
G_search_range = prior_from_U(cognitive_features) ∩ hardware_bounds(D)
S_obj(G)       = aggregate( aim_sessions | gain≈G, modes∈task_family )
S*             = argpeak S_obj  within range，再与 S_sub 对齐
confidence     ↓ if cognitive_state_poor or N_sessions 不足
```

### 8.4 和「专用校准关」的关系

- **日常 aim 数据**：样本多，但感度几乎不变 → 擅长期纵向、弱于横比多 G。  
- **认知数据**：丰富 \(U\) 与「能不能测」，**不能替代**多增益实验。  
- **sens-finder**：短、随机化、多 G → 仍是 \(S^*_{\text{obj}}\) 的主路径。  
- 最佳产品形态：**认知先验缩范围 → 短校准定 \(S^*\) → 日常 aim 日志做验证/漂移报警**。

### 8.5 工程缺口（要综合就先补这些）

- [x] Aim：**按局**存指标，并写入当时 `profileId / sensitivity / DPI`  
- [x] 认知：suite `DrillResult[]` 持久化（不只 schulte）  
- [x] 统一事件模型：`source: aim|drill|calib`，便于以后拟合  
- [x] 明确「综合」API 边界：先验 / 门控 / 任务权重 ≠ 直接输出 sens

## 9. 产品流程草案

```text
1. 输入：游戏档案、DPI、（可选）当前感度 / 控制习惯
2. 声明：本次推荐针对「任务族 X」；客观与主观可能不一致
3. 校准实验：多增益条件 × 重复 × 顺序随机；条件间相对步长
4. 拟合：S_obj(G)、S_sub(G) + 置信区间
5. 独立短验证关
6. 输出：cm/360 → in-game sens；推荐点 + 建议区间；一键写入 settings
7. 复测：平台期 / N 天后提示；日常可用小扰动精修（路线 C）
```

存储对齐：`SensitivitySettings = { profileId, sensitivity }`；建议另存推荐历史（含任务族、DPI、客观/主观分数、验证结果）。

## 11. 开放问题（下一轮拍板）

已拍板（Scope C 落地，2026-03-21）：

1. 默认任务族：**平衡**；开局可选 `balanced | flick | micro`（追踪族后续）。  
2. 冲突：推荐 = **\(S_{\text{obj}}\) 可接受带内最大化 \(S_{\text{sub}}\)**；UI 另示表现最佳 / 最舒适。  
3. 输出：**点估计 + cm/360 区间 + 对照两点**。  
4. DPI：**校准与写入推荐前强制填写**。  
5. 跨游戏：**存 cm/360**，apply 时按当前 profile yaw 换算。  
6. 冷启动：以**当前 sens → cm/360** 为 \(S_0\)。  
7. hold-out：**必须**。  
8. 多源：L1 局日志 + L3/L4 认知先验门控 + L5 sens-finder 主估计（本版已上）。  
9. 任务权重：按用户所选任务族加权 Fitts 变体（非固定 50/50）。
